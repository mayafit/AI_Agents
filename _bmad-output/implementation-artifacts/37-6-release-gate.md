- **D3 `--expect-update` and `EXPECT_UPDATE`.** NFR84's `current` is a property of a tree whose records equal `main`'s — true on `main` and on a tag, false by design on a branch that bumps the version (that branch reports `ahead` until it merges). So the CI step resolves the expectation from `GITHUB_REF`: `current` on `refs/heads/main` and `refs/tags/*`, `current,ahead` elsewhere. `could-not-check` is never in the list: a runner is online, so a read failure is a finding (a private repository, a renamed file, a GitHub outage). `newer-available` is never accepted either: a branch behind `main` must rebase. The comma list is explicit over a `--allow-ahead` flag so the log names the accepted states.
