# Story 36.5 — `AGENTS.md` Two-Writer Test Against v7 `bmad-project-context`

Status: backlog
Blocked on: 36-1
Wave: 1 (parallel with 36.3, 36.4)

**FR:** FR278 (second half: the `AGENTS.md` two-writer case is covered by an integration test asserting neither writer clobbers the other's block or user prose). **NFR:** NFR46 (byte-identical in-marker content on re-stamp), NFR49 (user content preserved). **Decision inputs:** P5-11.1 (`AGENTS.md` injection moves to `ma-standards-apply` in 37.2); Story 32.8 (cancelled; its AC structure reused).

## Story

As a **user who hand-edits `AGENTS.md` in a project that has both ma-agents and v7 `bmad-project-context`**,
I want each writer to touch only its own block, and v7's adoption flow not to dissolve ours,
so that running either one, in any order, never deletes the other's block or my prose, and uninstalling ma-agents leaves upstream's block and my text intact.

## Context

ma-agents writes `AGENTS.md` for the OpenCode target: `lib/agents.js:313` registers `{ template: 'agents-md.template.md', target: 'AGENTS.md', merger: 'markdown-markers' }`, processed by `markdownMarkersMerger` (`lib/installer.js:1332`) with `<!-- MA-AGENTS-START -->` / `<!-- MA-AGENTS-END -->`; `MA_AGENTS_YES` sets its yes mode (`:1335`); when the file does not exist it writes the whole template with a leading "Generated by ma-agents" comment (`:1345`). Uninstall lists `AGENTS.md` among five injection files (`lib/uninstall.js:45-51`, entry `:50`), strips the block with the regex in `stripMarkerBlock` (`:58-62`) and deletes the file when the rest is blank (`:220-224`). `test/agents-md.test.js` covers ma-agents alone.

v7's writer is different in kind from 6.12's. At `e734d3a`, `bmad-project-context` is **LLM-driven, not a script**: its block markers are `<!-- bmad:context -->` / `<!-- /bmad:context -->` (`skills/bmad-project-context/references/template.md:17`, `:52`); it detects intent — `setup`, **`adopt`** ("an instruction file has content but no managed block, whatever its state and whoever wrote it … every instruction in it enters the ledger", `SKILL.md:29`), `refresh`, `record`, `audit`; on approval it "splice[s] between the markers — the splice itself touches nothing outside them" (`:72`); and adoption may propose "a `CLAUDE.md` reduced to `@AGENTS.md`" (`:97`). So the deterministic splice can be tested by simulation, but the adopt ledger — which may propose relocating or deleting the MA-AGENTS block as an "existing instruction" — can only be observed by running the skill, and `CLAUDE.md` (also in `INJECTION_FILES`, `lib/uninstall.js:46`) becomes a second two-writer file.

## Acceptance Criteria

**Simulation rule:** the simulated upstream write reads its marker strings and block template **at test time from the pinned tree** (`skills/bmad-project-context/references/template.md`, 36.3 snapshot or `BMAD_V7_TREE`); no upstream marker or template text is typed into the test. The test asserts the values read are non-empty and the file exists, so a moved upstream file fails the test. Tags: **[v7-carries]** / **[pre-release-only]** as in 36.1.

1. **Order A (ma-agents first), simulated splice.** [v7-carries] Empty project → ma-agents install (OpenCode) → simulated upstream splice of a `bmad:context` block. Assert: MA-AGENTS block byte-identical; upstream block present exactly once; ma-agents' leading comment and template prose unchanged.
2. **Order B (upstream first).** [v7-carries] Empty project → simulated upstream block → ma-agents install. Assert: upstream block byte-identical; MA-AGENTS block present once; ma-agents did **not** write its full template over the existing file (`lib/installer.js:1345` path not taken).
3. **User prose, both orders.** [v7-carries] Fixture with user paragraphs before, between and after the two blocks; each writer re-runs twice, interleaved; every user paragraph byte-identical and in place.
4. **Idempotence.** [v7-carries] Re-running either writer with unchanged input leaves the file byte-identical (sha256 before/after, NFR46).
5. **Uninstall keeps upstream.** [v7-carries] `ma-agents uninstall` on the A and B results removes only the MA-AGENTS block; upstream's block and user prose remain; the file is not deleted. A fixture with only the MA-AGENTS block is deleted (the `:220-224` blank-file rule still holds).
6. **Marker non-interference.** [v7-carries] The upstream markers read at test time do not match `stripMarkerBlock`'s regex (`lib/uninstall.js:61`), and `<!-- MA-AGENTS-START -->…END` is not matched by a matcher built from the upstream markers.
7. **CRLF.** [v7-carries] AC1–AC3 repeated with a CRLF fixture; no writer converts the other's block or the user's prose to LF (byte compare).
8. **Real adopt run, recorded (the v7 risk).** [pre-release-only — LLM behaviour, re-run by 36.7 at GA] In a scratch project holding an ma-agents-written `AGENTS.md` (Order A result) and a `CLAUDE.md` containing the MA-AGENTS block, the real `bmad-project-context` skill from the pinned tree is run once in `adopt` intent. Recorded verbatim: the intent it detected, every ledger entry touching the MA-AGENTS block or `CLAUDE.md` (decision `retain / rewrite / relocate / automate / delete` and reason), and the file bytes after approval of the default proposal. PASS: the MA-AGENTS block survives byte-identical. Otherwise the finding goes to the PO as a UX defect with a proposed mitigation (e.g. a `persistent_facts` line on `bmad-project-context` naming the MA-AGENTS block as managed, validated by 36.4 AC4), and to 37.2 (`ma-standards-apply`) as a design input. The test does not simulate this AC.
9. **`INJECTION_FILES` reviewed for v7.** [v7-carries] `lib/uninstall.js:45-51` is reviewed against the pinned skill: `CLAUDE.md` is in scope because adoption may rewrite it (`SKILL.md:97`) — AC3 and AC5 are repeated for `CLAUDE.md` with the simulated `@AGENTS.md` reduction; the other three files are recorded as untouched by v7 or covered the same way.
10. **Mutation-checked.** (m1) the merger writes the full template whenever markers are absent → AC2 red; (m2) `stripMarkerBlock` made greedy → AC5 red with a second marker-like block; (m3) the merger normalises line endings → AC7 red; (m4) uninstall deletes `AGENTS.md` unconditionally → AC5 red; (m5) the pinned template path pointed at a nonexistent file → the simulation fails loudly, no fallback literal.
