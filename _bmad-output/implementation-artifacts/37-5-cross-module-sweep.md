## Story

As the **maintainer of `ma-bmad-extensions`**,
I want one CI check that reads every owned skill and fails when a skill names a configuration key or file the pinned BMAD commit does not define, carries the reserved `bmad-` prefix, reaches into another module without its record declaring that skill, names a sprint skill FR296 removed, or names a 3.x project file outside a migration — and I want the first run of that check audited by Gadi, with every finding fixed,
so that the four modules of 4.0.0-beta.1 are independent in fact and not only by declaration, and the release gate (37.6) inherits a tree where nothing reaches into another module, into 3.x, or into a configuration key that does not exist.
