- **D1 Engine: copied as-is behind a staging adapter, not rebuilt.** The engine's contract is a project root whose `_bmad/bmm/config.yaml` it reads and whose `_bmad-output` it scans, with 3.x file names as its classifier, and the "reads no v6 key" rule cannot be met by pointing it at the project. The alternative, a rebuild from `lib/knowledge-atlas/src/` with a v7 reader, would mean esbuild and the TypeScript sources in this repository or a second committed bundle in ma-agents outside this story's files, and a renderer that diverges from Epic 29's. So `build_atlas.py` (Python, PEP 723, standard library) reads the v7 store itself and builds a scratch project for the engine: `<stage>/_bmad-output/` with the store's own Markdown and diagram files copied unchanged, one `ticket-board.md` per initiative and one page per ticket written from the breakdown tables and the plans, and a `package.json` carrying the project title (the project's `package.json` `name` when it has one, else the root folder's name). The engine runs as `node atlas.cjs <stage> --out <stage>/atlas` and finds no configuration, no tracker and no `knowledge-graph.json` there; the site then replaces the Atlas folder. Costs: the engine's fileId prefix is the stage's folder name, so page slugs read `bmad-output-initiative-<slug>-…html` whatever `core.output_folder` is; the engine bundle's text still contains the 3.x names (see the PO items); every run is a full build (the engine's incremental manifest is never reused — a few seconds on the fixture).
- **D2 Ticket pages and boards.** A ticket page is named `<epic id>-<entry id>-<slug>.md` so the engine classifies it `story` and gives it a file-level node; the board uses the engine's `Epic N` / `Story N.M` tokens so the graph links epics, tickets and the documents that mention them. Status is the plan's `status` verbatim; the board state is `tickets.py`'s (`STATE_OF`, restated in the script with a comment naming its origin): `tracker_status` of the leaf when set, else the state of the status, `planned` for an entry with neither leaf nor plan, `blocked` for an unknown status (listed under `Problems`, as `tickets.py status` lists it). A spike or bug is `Spike N.M` / `Bug N.M`. An epic file without `status` shows `not started`. The 3.x engine badges only its five statuses, so the pills on the home page count `done`, `in-progress`, `ready-for-dev`, `review`, `backlog`; the v7 values are in the page and row text, which is what FR305 asks for.
