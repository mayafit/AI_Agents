# Sprint Management — Shared Guardrails

All stories in Epics 11, 12, and 17 inherit the following guardrails. Individual story specs reference this file rather than repeating these rules verbatim.

## Universal Constraints

- Do NOT add any new npm dependencies
- Do NOT modify `lib/installer.js`, `lib/agents.js`, or `bin/cli.js`
- Do NOT modify any files under `_bmad/bmm/workflows/` or `_bmad/core/` — extensions go in `lib/bmad-extension/`
- Do NOT place extension workflows anywhere other than `lib/bmad-extension/workflows/`

## Data Authority Rules

| Concern | Authoritative Source | Read By |
|---|---|---|
| Sprint entity (membership, capacity, dates, status) | `sprints/sprint-{id}.yaml` | 17.4, 17.5, 17.6, 17.8 |
| Item priority ordering and backlog | `backlog.yaml` | 17.4, 17.5, 17.6, 17.7, 17.8 |
| Sprint membership (old format, **deprecated**) | `sprint-plan-{n}.yaml` | 12.2, 12.3, 12.4 *(superseded by Epic 17)* |
| User story execution status | `sprint-status.yaml` (**derived** — regenerated by 17.8) | 12.2, 12.4, 17.8 |
| Bug story metadata (type, severity, title, status) | `bug-{slug}.md` YAML frontmatter | 12.2, 12.4, 17.3, 17.6 |

**Never write sprint assignments to sprint-status.yaml.** These are separate concerns.

**Concurrency note:** Glob-then-write is not atomic; concurrent sprint modification is unsupported. Only one agent/user should modify a sprint file at a time.

## Sprint Artifact Naming

- Sprint artifacts: `_bmad-output/implementation-artifacts/sprints/sprint-{id}.yaml`
- Sprint discovery glob: `sprints/sprint-*.yaml`
- Sprint artifacts include `created_date` and `last_modified` ISO timestamp fields
- `last_modified` is updated on every write (concurrency guard)
- `created_date` is set once at creation and never updated

## Sprint Status Transitions

| From | To | Condition |
|---|---|---|
| `planning` | `active` | No other sprint is `active` |
| `active` | `closed` | Always allowed |
| `closed` | `active` | **INVALID** — no reopening closed sprints |
| `closed` | `planning` | **INVALID** |
| `active` | `planning` | **INVALID** — must close first |
| (creation) | `active` | **INVALID** — always start as `planning` |
| (creation) | `closed` | **INVALID** — always start as `planning` |

**Rules:**
- Only one sprint can be `active` at a time
- New sprints always start in `planning` status
- Closed sprints cannot be reopened — create a new sprint instead
- Sprints cannot be deactivated without closing

## Item ID Format Contract

Item IDs stored in sprint `items` arrays follow these formats:

- **Story IDs:** `{epic}-{story}-{slug}` (e.g., `5-5-explicit-parameter-passing`) — matches sprint-status.yaml key format
- **Bug IDs:** `BUG-{slug}` (e.g., `BUG-path-spaces`) — matches bug story file naming `bug-{slug}.md` but with uppercase `BUG-` prefix

This contract is consumed by Stories 17.4 (writes items), 17.5 (removes items), 17.6 (cleanup), and 17.8 (display).

## Backlog Model (Story 17.2)

The flat prioritized backlog is stored in a single file: `_bmad-output/implementation-artifacts/backlog.yaml`

### Backlog YAML Schema

```yaml
backlog:
  - id: "5-5-explicit-parameter-passing"   # Story: {epic}-{story}-{slug}
    type: story                             # enum: story | bug
    epic: 5                                 # int for stories, null for bugs
    title: "Explicit Parameter Passing"     # always quoted
    priority: 1                             # sequential int, 1 = highest
    status: backlog                         # from sprint-status.yaml or bug frontmatter
    sprint: null                            # sprint-{id} if assigned, null if not
    severity: null                          # null for stories
  - id: "BUG-path-spaces"                  # Bug: BUG-{slug}
    type: bug
    epic: null                              # bugs don't belong to epics (FR64)
    title: "Fix space-in-path bug"
    priority: 2
    status: backlog
    sprint: "sprint-3"                      # assigned to sprint-3
    severity: high                          # critical|high|medium|low
```

### Backlog Rules

- Done items are NEVER included in the backlog (archived by Story 17.6)
- Bug entries MUST have `epic: null` (FR64)
- Bug entries MUST have non-null `severity`
- Priority values are always sequential integers 1..N after any modification (no gaps, no ties)
- Generating the backlog is idempotent: re-running with no source changes produces identical output
- Existing `priority` and `sprint` assignments are preserved on re-generation

### sprint-status.yaml Is Now Derived (Story 17.8)

- `sprint-status.yaml` is regenerated by `/sprint-status-view` from `backlog.yaml` + sprint files
- Manual edits to `sprint-status.yaml` will be overwritten on next regeneration
- The `# updated:` comment in the header is preserved and updated with the regeneration timestamp

## Bug Lifecycle (Story 17.3)

Bug status is tracked in the bug file's own YAML frontmatter `status` field:

```
backlog -> ready-for-dev -> in-progress -> review -> done
```

### Extended Bug Frontmatter

```yaml
---
type: bug
severity: critical           # critical|high|medium|low
title: "Login fails"         # always quoted
version_found: "3.0.0"      # optional, empty string if skipped
bug_type: regression         # regression|functional|performance|security|ui|data|integration|other
status: backlog              # backlog|ready-for-dev|in-progress|review|done
---
```

- `version_found` and `bug_type` are optional (backward compatible)
- Missing `version_found` -> treat as empty/unknown
- Missing `bug_type` -> treat as `functional`
- Missing `status` -> treat as `backlog`
- Stories track status in `sprint-status.yaml` — bugs do NOT appear there
- Done bugs are archived to `done/bug-{slug}.md` by Story 17.6

## Dual-Write Contract (Stories 17.4, 17.5)

When assigning or removing items from sprints, BOTH files must be updated:

1. `backlog.yaml` — set/clear the `sprint` field on the item
2. `sprints/sprint-{id}.yaml` — add/remove the item ID from the `items` array, update `last_modified`

If one write fails, the other must be rolled back or the user must be warned about inconsistency.

### Status Invariant (Story 17.5)

Removing an item from a sprint NEVER changes the item's status or priority. The item simply becomes unassigned (`sprint: null`) while retaining its current state.

## Done Item Archive (Story 17.6)

- Done items are moved to `_bmad-output/implementation-artifacts/done/` subfolder via file rename (preserves git history)
- Files are NOT overwritten if already in `done/` — skip with warning
- Done items are removed from: sprint files `items` array, `backlog.yaml`, `sprint-status.yaml`
- Backlog priorities are re-numbered 1..N after done item removal

### Sprint Auto-Close

When all items in a sprint are removed (via cleanup-done):
- If sprint status is `active`: auto-close to `closed`
- If sprint status is `planning`: no change (empty planning sprint is valid)

### Epic Auto-Done

When all story keys for an epic are removed from `sprint-status.yaml` (all done), the epic status is set to `done`.

## Prioritization Rules (Story 17.7)

### Criteria (Weighted)

| Criterion | Weight | Description |
|---|---|---|
| Blocking dependencies | Highest | Items that unblock others get top priority |
| Severity (bugs) | High | Critical > High > Medium > Low |
| Business value | Medium | Inferred from epic priority and story position |
| Item type | Low | Bugs slightly above stories when severity/value equal |
| Age | Lowest | Older items above newer when all else equal |

### Dependency Inference

- Same-epic stories are sequentially dependent by default (17-1 before 17-2 before 17-3)
- Cross-epic dependencies from epics.md "Dependencies" sections
- Scrum Master can override any dependency warning

### Audit Logging

Every reprioritization appends a header comment to `backlog.yaml`:
```yaml
# Reprioritized: {date} — {reason}
```

## Bug Story File Contract (Epic 11 → Epic 12/17 integration)

Bug stories created by `create-bug-story` (11.2) are discovered by sprint workflows via:

1. Glob: `_bmad-output/implementation-artifacts/bug-*.md`
2. YAML frontmatter parsing — required fields: `type: bug`, `severity`, `title`

Bug stories are **not** tracked in sprint-status.yaml. They are peers to user stories in the flat backlog (FR65).
