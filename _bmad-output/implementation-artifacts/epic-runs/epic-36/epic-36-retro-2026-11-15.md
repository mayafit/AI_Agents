## What went well

- **The spike paid for itself.** 36.1 turned the Node floor (20.12 → 22.20), the `python-install-dir` rejection, the private-repository `could-not-check` and the CLAUDE.md-adjacent adoption behaviour into evidence before any of 36.2–36.5 wrote code; every downstream story started from its change set.
- **Evidence from outside the code.** 36.3 recomputes hashes in the test rather than trusting the builder; 36.4 reads slots from the pinned tree; 36.5 hashes the committed fixture against the pinned blob; 36.6 ties `bmadRef.core` to the build's `git rev-parse HEAD` and to 36.5's independently fetched template. Mutants were run for 36.3, 36.4, 36.5 and 36.6 and all went red.
- **Determinism held across platforms and days.** `bundle/manifest.json` hashed `8515f1d4…` in 36.3 (Windows and Linux) and again in 36.6 (Windows locally and GitHub Actions) — the Skills CLI's floating dependency ranges did not drift in that window.
- **The offline runtime proof moved into CI unchanged.** 36.2's five-script run and its controls ran in GitHub Actions under `--network none` on the first attempt.

## What did not go well

- **The chain had never run whole.** Stories 36.2–36.5 each recorded "full `npm test` chain not run". The first full run (36.6) found two new failures the stories had introduced: `release-gate-epic-31` (six new shipped files, counts not re-pinned) and `customize-contract-v7` m2 (an LF-only regex that breaks in a Windows autocrlf checkout). Both are small, both would have been caught by the per-file runner if it had existed earlier.
- **"Merge-blocking" was specified without checking the platform.** AC3 requires a required status check; the repository is private on the free plan and branch protection is unavailable (HTTP 403). The gate verdict is FAIL on that item alone.
- **The existing offline-install job has been red for 33 runs** (FR250 notice facts) with no bug record; every Epic 36 PR showed a red check that everyone learned to ignore.
- **`.gitignore` hides new `.github/` files** (`.github/` excluded, negations cannot re-include); new CI files need `git add -f`.
